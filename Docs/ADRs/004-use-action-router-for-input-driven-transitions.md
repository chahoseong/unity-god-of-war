# 004: 입력 기반 상태 전이(Input-Driven Transition) 제어를 위해 행동 라우터(Action Router)를 사용함

## 상태 (Status)

승인됨 (Accepted)

## 날짜 (Date)

2026-10-22

## 맥락(Context)

우리는 ADR-001에서 캐릭터 행동 상태를 제어하기 위해 모듈형 유한 상태 머신(Modular FSM)을 채택했다. 이에 따라 이동, 회피, 공격, 가드 등 각 행동이 독립된 상태(State) 클래스로 분리되었으나, 플레이어 입력에 따른 상태 간 전이(State Transition)를 어떻게 중재하고 결정할 것인가에 대한 구체적인 구조가 필요하다.

3인칭 근접 액션 전투에서는 다음과 같은 엄격하고 복잡한 입력 전이 규칙을 처리해야 한다:
- **후딜레이 캔슬(Cancel Window)**: 공격 중 후딜레이 구간에서 회피, 가드, 또는 이동 입력이 들어오면 현재 동작을 취소하고 해당 행동으로 즉시 전이해야 한다.
- **상태 내부 연계(Combo & Sequence)**: 공격 진행 중 동일한 공격 버튼을 누르면 다음 콤보 타수를 실행하고, 퀵스텝 중 회피 버튼을 다시 누르면 2단 구르기(Roll)로 연계해야 한다.
- **우선순위 역전**: 다음 타수가 예약된 상태에서 회피를 입력한 경우, 회피가 우선되어 공격 예약을 끊고 즉각적인 생존 행동으로 이어져야 한다.
- **선입력 버퍼링(Input Buffering)**: 현재 행동이 끝나거나 캔슬 가능 시점에 도달하기 직전에 입력된 조작을 유실하지 않고 기억해 두었다가 적시에 실행해야 한다.

만약 각 상태 클래스가 캔슬 대상 상태를 직접 참조하여 전이하면, 예를 들어 `AttackState`가 `QuickStepState`, `GuardState` 등을 직접 참조하게 되어 상태 간 결합도(Coupling)가 급격히 증가한다. 반대로 (현재 상태, 입력) 조합을 거대한 2차원 매트릭스 표로 관리하면 새로운 상태가 추가될 때마다 모든 상태 간의 전이 행렬을 갱신해야 하는 관리 비용이 발생한다.

따라서 입력 기반 전이에서 상태 간의 직접 참조를 제거하고, 전이 규칙과 선입력 버퍼링을 한곳에서 일관되게 관리할 수 있는 중앙 중재 구조가 필요하다.

## 결정(Decision)

**우리는 플레이어 입력에 따른 상태 전이를 중재하고 제어하기 위해 플레이어 전용 컴포넌트인 행동 라우터(Action Router)를 사용한다.**

행동 라우터는 플레이어의 입력(버튼 입력 및 유지 입력)을 수신하여 대상 상태를 결정하는 컴포넌트이며, 개별 상태는 구체적인 전이 대상을 알지 못한 채 오직 허용 행동 종류(끼어들기 가능 여부)만을 체크리스트로 응답한다.

상세 결정 사항은 다음과 같다:

### 1. 라우터의 기본 역할 및 규칙
- **라우팅 결정권**: 입력이 들어오면 행동 라우터가 라우팅 테이블(Routing Table)을 참조하여 대상 상태를 결정한다. 현재 상태는 허용 행동 종류만 응답한다.
- **라우팅 테이블 구성**: 라우팅 테이블은 `(입력, 행동 종류, 대상 상태, 시작 조건)`으로 정의하며, 테이블 내에 "현재 상태" 열은 두지 않는다.
- **상태 간 결합도 분리(Decoupling)**: 현재 상태는 입력 캔슬로 넘어갈 대상 상태를 알지 못한다 (예: `AttackState` 코드 내에 `QuickStepState`나 `GuardState`에 대한 참조가 전혀 없음). 현재 상태는 라우터에 자신이 허용하는 행동 종류만 제공한다.

### 2. 제어 범위 (Scope)
- **버튼 입력과 유지 입력의 일원화**: 단발성 버튼 입력(공격, 회피, 가드 등)뿐만 아니라 유지 입력(이동 스틱)도 모두 행동 라우터가 일원화하여 처리한다.
  - 이를 통해 이동 캔슬 판정이 상태마다 중복 구현되는 문제를 방지하고, 모든 캔슬 규칙을 라우터 한곳에 모은다.
- **유지 입력의 동일 상태 전이 무시 규칙**: 유지 입력은 매 프레임 판정하므로, 라우터가 결정한 대상 상태가 현재 활성 상태와 같으면 전이를 무시한다.
  - 이 규칙은 유지 입력에만 적용되며 버튼 입력에는 적용되지 않는다. 따라서 공격 연계 구간 종료 후 공격 버튼을 눌러 새 1타를 시작하는 등 동일 상태로의 재진입(`AttackState` → `AttackState`)은 정상적으로 처리된다.

### 3. 상태와 라우터의 약속 (Protocol)
- **행동 종류 체크리스트**: 각 상태는 판정 시점에 자신이 현재 받아 줄 수 있는 행동 종류(이동·회피·가드·공격)를 체크리스트로 라우터에 응답한다.
- **묵시적 기본값 배제 (Fail-Fast 정책)**: 시스템 안정성을 위해 '선언이 없으면 전부 허용/전부 거절'과 같은 묵시적 기본값을 두지 않는다.
  - 모든 플레이어 상태는 허용 행동 체크리스트를 명시적으로 선언해야 하며, 선언 누락은 컴파일 시점에 즉시 감지되어야 한다. 이를 통해 실수를 런타임이 아닌 컴파일 시점에 드러내고, 상태 파일 상단에서 허용 정책을 명확히 파악할 수 있도록 한다.
  - ADR-003(Core 독립성)에 따라 도메인 중립적인 Core 어셈블리의 `IState`를 오염시키지 않고, 이 선언 의무는 플레이어 도메인 경계 안에서 강제한다 (행동 라우터 역시 플레이어 전용 컴포넌트이다).

### 4. 입력 처리 흐름 및 우선순위 (Priority & Buffering)
- **상태 내부 연계 우선 질의**: 입력이 들어왔을 때, 라우터는 라우팅 테이블을 조회하기 전에 먼저 현재 상태에 해당 입력이 내부 연계(공격 콤보 다음 타수, 퀵스텝 중 구르기 연계 등)에 해당하는지 질의(Query)한다.
  - 상태가 처리하지 않은 경우에만 라우터 표의 전이 규칙으로 넘어간다.
  - 이 처리 흐름 덕분에 맥락 절에서 언급한 '우선순위 역전' 요구사항이 자연스럽게 성립한다. 회피는 공격 상태의 후속 행동이 아니므로 상태가 거절하여 라우터 표로 넘어가고, 후딜레이 구간의 체크리스트가 회피를 허용하므로 회피 상태로 전이되며, 이때 공격 상태를 빠져나오면서 예약된 다음 타는 소멸하기 때문이다.
- **실제 처리 시에만 처리 완료 반환**: 상태는 실제로 콤보나 연계를 이어 갔을 때만 `Handled: true`를 반환한다.
  - 상태가 거절한 입력은 라우터에 그대로 남게 되므로, 선입력 버퍼링(Input Buffering)을 라우터에 일원화하여 관리할 수 있다.

### 5. 강제 상태 전이와의 경계 분리
- **입력 전이와 강제 전이의 분리**: 피격, 가드 브레이크, 스턴, 사망 같은 외적 전이는 라우터 밖에서 전투 시스템이 FSM을 통해 직접 처리한다.
  - 라우터의 범위를 플레이어 입력으로 한정하여, 피격 판정, 슈퍼아머, 가드/패링 판정 등의 전투 도메인 로직이 라우터와 섞이지 않도록 방지한다.
- **입력 버퍼 비우기(Flush)**: 강제 전이가 발생하면 라우터가 기억하던 선입력 버퍼를 즉시 비워, 피격 후 의도치 않은 조작이 지연 발동되는 문제를 방지한다.

## 대안(Alternatives)

- **A. 상태 간 직접 전이 (State-to-State Direct Transition)**
  - **장점**: 별도의 라우터나 중재 컴포넌트 없이 각 상태에서 즉시 다른 상태로 전환할 수 있어 초기에 빠르게 작성할 수 있다.
  - **단점**: 각 상태가 캔슬 대상 상태들을 직접 참조해야 하므로 결합도가 증가하고, 공격 후딜레이 캔슬이나 이동 캔슬 로직이 상태마다 중복 구현된다.
- **B. (현재 상태, 입력) 2차원 전이 행렬 (Transition Matrix)**
  - **장점**: 상태 전이 조합을 한눈에 매트릭스 형태로 파악할 수 있다.
  - **단점**: 새로운 상태나 입력이 추가될 때마다 행·열 전체를 채워야 하므로 중복이 표 내부 항목으로 전가될 뿐이다.
- **C. 버튼 입력 한정 라우터 (Button-Only Router)**
  - **장점**: 라우터가 단발성 버튼 입력만 처리하므로 구조가 단순해진다.
  - **단점**: 이동 캔슬 판정이 상태마다 중복되어, 캔슬 규칙을 일원화하려는 목적이 반감된다.
- **D. 상태-라우터 프로토콜 대안**
  - **정수 등급(Priority Tier)**: 허용 범위끼리 포함 관계일 때만 성립하여 "회피는 되고 공격은 안 됨" 같은 조합을 나타내기 어렵다.
  - **상태 내 판정 함수(Predicate)**: 캔슬 판정 로직이 다시 상태마다 분산된다.
  - **체크리스트 미선언 시 전부 허용**: 이동 스틱만 밀어도 매 프레임 이동 상태로 끊기는 문제가 발생한다.
  - **체크리스트 미선언 시 전부 거절**: 입력이 동작하지 않을 때 원인을 찾기 번거롭다.
- **E. 우선순위 및 입력 처리 대안**
  - **라우터 표를 먼저 확인**: 연계 구간 중 누른 공격이 1타부터 다시 시작될 수 있다.
  - **라우터 표에 예외 줄 추가**: 사실상 (현재 상태, 입력) 표 구조로 되돌아가게 된다.
  - **무시하는 입력도 처리 완료 반환**: 라우터가 입력 유무를 인지하지 못하므로 선입력 버퍼링을 상태마다 따로 만들어야 한다.
- **F. 피격 등 강제 전이를 포함한 통합 라우터**
  - **장점**: 모든 상태 전이의 단일 진입점이 된다.
  - **단점**: 라우터가 전투 판정의 책임과 섞여 비대해지며, 라우터의 본래 목적인 '입력 기반 전이 중재' 범위를 벗어난다.

## 결과(Consequences)

입력 기반 상태 전이에서 대상 상태에 대한 직접 참조가 사라지므로 상태 간 결합도가 크게 낮아지고, 모든 캔슬 규칙이 라우터 한곳에 모인다. 새로운 행동이 추가될 때도 각 상태에 '어디로 갈지'를 적지 않고 허용할 행동 종류만 체크리스트에 반영하면 되므로 구조적 유연성이 확보된다. 또한 버튼 입력과 유지 입력을 일원화하고 거절된 입력을 라우터가 보존함으로써, 선입력 버퍼링(Input Buffering)을 라우터에 일원화하여 안정되게 관리할 수 있다.

반면 행동 종료 후의 자연 복귀(`AttackState`나 `QuickStepState`가 끝난 뒤 `LocomotionState`로 복귀)나 동일 계열의 후속 연계(`QuickStepState`에서 `DodgeRollState` 연계)에는 여전히 상태 간 참조가 남는다. 또한 모든 플레이어 상태는 체크리스트를 선언해야 하는 규칙이 강제되며, 새로운 행동 종류가 추가될 경우 이를 받아 줘야 하는 상태들의 체크리스트를 갱신해야 한다.
