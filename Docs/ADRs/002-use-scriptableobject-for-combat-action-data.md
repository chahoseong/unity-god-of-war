# 002: 전투 액션(Combat Action) 데이터 정의를 위해 ScriptableObject를 사용함

## 상태 (Status)

승인됨 (Accepted)

## 날짜 (Date)

2026-10-18

## 맥락(Context)
우리는 약공격 콤보, 강공격 콤보, 패링 카운터 및 향후 확장될 스턴 처형기나 쿨타임 스킬 등 다양한 전투 액션(Combat Action)의 데이터를 정의하고 관리해야 한다. 각 전투 액션은 데미지, 경직도, 유효 타격 구간(Active Window), 후딜레이 캔슬 구간(Cancel Window)과 같은 수치 데이터뿐만 아니라, 재생할 애니메이션 클립이나 이동 속도 커브(`AnimationCurve`)와 같은 유니티 엔진 에셋 참조를 함께 포함한다. 또한 전투의 타격감과 조작감을 맞추기 위해 플레이테스트 과정에서 이 타이밍 수치들을 빈번하게 수정해야 한다.

선택할 수 있는 옵션으로는 각 상태 클래스나 프리팹 컴포넌트 필드에 수치를 직접 정의하는 방식, 유니티의 **`ScriptableObject` 데이터 에셋**을 사용하는 방식, 또는 **JSON/CSV 같은 외부 데이터 테이블**을 사용하는 방식이 있다.

## 결정(Decision)
**우리는 전투 액션 데이터 정의를 위해 유니티의 ScriptableObject를 사용한다.**

액션 전투 시스템의 완성도를 높이려면 애니메이션 클립과 프레임 구간 타이밍(선딜레이, 히트박스 활성 구간, 후딜레이 캔슬 구간)을 한곳에서 직관적으로 묶어 관리하고, 코드 재컴파일 없이 에디터에서 즉각 수치를 조정하며 테스트할 수 있는 환경이 필요하다.

`ScriptableObject`로 액션 데이터를 분리하면 유니티 에디터 인스펙터에서 애니메이션 클립과 타이밍 수치를 직접 연결하고 실시간으로 튜닝할 수 있으며, 공격 실행 로직과 개별 액션 데이터를 분리하여 향후 새로운 콤보나 스킬이 추가되는 변화에 유연하게 대응할 수 있다.

## 대안(Alternatives)
- **상태 클래스 또는 프리팹 컴포넌트 내 직접 정의**
  - **장점**: 별도의 데이터 에셋 파일을 생성할 필요 없이 코드나 캐릭터 프리팹 하나에서 바로 값을 확인할 수 있다.
  - **단점**: 공격 타수나 스킬이 늘어날수록 컴포넌트 필드가 비대해지며, 동일한 액션 데이터를 다른 프리팹이나 에이전트 작업 단위에서 독립적으로 재사용·교체하기 어렵다.
- **유니티 ScriptableObject 데이터 에셋**
  - **장점**: 애니메이션 클립, 커브(`AnimationCurve`) 등 유니티 고유 에셋 참조와 수치 데이터를 별도 파싱 코드 없이 직렬화할 수 있으며, 코드 수정 없이 에셋 추가만으로 새로운 공격 액션을 확장할 수 있다.
  - **단점**: 액션 개수만큼 프로젝트 내에 `.asset` 파일이 생성되며, 런타임 중 에셋 데이터를 직접 수정할 경우 원본 데이터가 오염될 수 있다.
- **외부 데이터 테이블 (JSON / CSV)**
  - **장점**: 스프레드시트 등을 활용해 대량의 수치 데이터를 일괄 편집하거나 비교하기에 유리하다.
  - **단점**: 애니메이션 클립이나 커브 같은 유니티 에셋을 직접 참조할 수 없어 별도의 경로 매핑 및 파싱 파이프라인을 구축해야 하며, 소규모 버티컬 슬라이스에서는 불필요한 구현 부담이 된다.

## 결과(Consequences)
공격 상태 로직(`AttackState` 등)은 전달받은 데이터를 시간 흐름에 따라 재생하는 역할만 수행하게 되므로, 새로운 공격 콤보나 쿨타임 스킬을 추가할 때 기존 C# 코드를 수정할 필요 없이 새로운 `ScriptableObject` 에셋만 생성하여 연결하면 된다.

반면 `ScriptableObject`는 프로젝트 전역에서 공유되는 데이터 에셋이므로, 액션 실행 중 매 프레임 변하는 런타임 상태(예: 현재 경과 시간, 이번 공격에서 이미 타격한 대상 목록)를 에셋 내부에 저장하면 데이터가 오염된다. 따라서 개발자와 AI 에이전트는 런타임 가변 상태를 반드시 캐릭터의 상태 인스턴스 측에 분리하여 관리해야 하며, 액션 종류가 늘어남에 따라 다수의 `.asset` 파일을 폴더별로 체계적으로 관리해야 한다.
